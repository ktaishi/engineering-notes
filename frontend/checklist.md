# フロントエンド・UX・アクセシビリティチェックリスト

> 最終確認日：2026年11月15日

Web の画面（フロントエンド）を作るときに確認するチェックリストです。
表示の速さ、使いやすさ、アクセシビリティ（障害のある人や高齢者を含め、誰もが使えること）は、後から直すほど費用がかかります。設計の段階から組み込むことを重視しています。

---

## 基本方針

1. **利用者が実際に体感する速さを測る**
   - 開発者の高性能な端末ではなく、利用者の端末と回線を想定して、表示と操作の速さを確かめる
2. **アクセシビリティを最初から組み込む**
   - キーボードで操作できる、読み上げソフトで内容が伝わる、色だけに頼らない、といった基本を設計の段階で決める
3. **状態を漏れなく設計する**
   - 読み込み中、空のとき、エラーのとき、権限がないときの表示を、正常な表示と同じように設計する
4. **AI が作った画面は、実際に動かして確かめる**
   - コードが正しく見えても、表示の崩れや操作できない箇所があるため、画面を開いて確認する

---

## アクセシビリティと法令（日本）

- 2024年4月の障害者差別解消法の改正で、事業者による「合理的配慮の提供」が義務になりました
- Web サイトのアクセシビリティの向上は、合理的配慮を的確に行うための「環境の整備」として努力義務とされています。Web サイトの改修そのものが義務になったわけではありませんが、個別の申し出への対応は義務です
- 対応の目安として、JIS X 8341-3（WCAG に対応する日本の規格）や WCAG 2.2 のレベル AA が使われています

## チェックリスト

### 1. 表示の速さ

- [ ] Core Web Vitals（LCP：主要な内容の表示、INP：操作への反応、CLS：表示のずれ）を計測しているか
- [ ] 実際の利用者の環境での数値（フィールドデータ）を見ているか
- [ ] 画像を適切なサイズと形式で配信し、表示範囲外の画像を遅れて読み込んでいるか
- [ ] JavaScript の量を抑え、不要なライブラリを読み込んでいないか
- [ ] 静的なファイルを CDN から配信し、キャッシュを設定しているか
- [ ] 画像や広告の領域をあらかじめ確保し、表示がずれないようにしているか

### 2. 使いやすさ（UX）

- [ ] 読み込み中・空のとき・エラーのとき・権限がないときの表示を設計したか
- [ ] エラーメッセージが、何が起きたかと、どうすればよいかを伝えているか
- [ ] 入力フォームで、入力中の確認と、送信時の分かりやすいエラー表示があるか
- [ ] 二重送信を防いでいるか（送信中はボタンを押せないようにする）
- [ ] 主要な操作が、少ない手順でできるか
- [ ] スマートフォンとパソコンの両方で、表示と操作を確認したか

### 3. アクセシビリティ

- [ ] すべての操作を、キーボードだけで行えるか。操作中の位置（フォーカス）が見えるか
- [ ] 画像に、内容を伝える代替テキストがあるか（装飾の画像は読み上げない設定）
- [ ] 見出し、ボタン、リンク、フォームの項目名を、正しい HTML の要素で作っているか
- [ ] 文字と背景のコントラストが十分か
- [ ] 色だけで情報を伝えていないか（エラーを赤色だけで示さない）
- [ ] 文字を拡大しても、表示が崩れず読めるか
- [ ] 動画に字幕があるか、自動で動く表示を止められるか
- [ ] 自動の検査ツール（Lighthouse、axe など）で確認し、読み上げソフトでも主要な画面を確かめたか

### 4. 互換性と品質

- [ ] 対応するブラウザと端末を決め、確認しているか
- [ ] 主要な画面の表示を、スクリーンショットの比較などで確かめているか
- [ ] フロントエンドのエラーを収集し、監視しているか

### 5. セキュリティ

- [ ] 利用者の入力を表示するときに、エスケープしているか（XSS 対策）
- [ ] API キーなどの秘密情報を、フロントエンドのコードに含めていないか
- [ ] 権限の確認を、画面だけでなくサーバー側で行っているか
- [ ] Content Security Policy などのセキュリティ関連のヘッダーを設定しているか

### 6. AI を使う場合

- [ ] AI が作った画面を、実際にブラウザで開き、スクリーンショットをデザインと比べたか
- [ ] AI が作ったコードで、アクセシビリティ（要素の使い方、代替テキスト、キーボード操作）が抜けていないか確認したか
- [ ] AI に、自動の検査ツールの結果をもとに修正させたか

## AI への依頼テンプレート

```markdown
あなたはフロントエンドとアクセシビリティに詳しいエンジニアです。
以下の画面をレビューしてください。

## 画面の概要
{ 画面の目的、主な操作、対象の端末 }

## 対象
{ コード、スクリーンショット、Lighthouse や axe の結果 }

## 依頼内容
1. 添付のチェックリストと照らし合わせ、問題のある箇所を挙げてください。
2. 表示の速さ（Core Web Vitals）を悪化させている要因と、改善案を挙げてください。
3. キーボード操作、読み上げ、コントラストなど、アクセシビリティの問題を挙げてください。
4. 読み込み中・空・エラー・権限なしの表示が設計されているか確認してください。
5. 指摘ごとに、修正の優先度（必須・推奨・任意）と修正案を書いてください。
```
